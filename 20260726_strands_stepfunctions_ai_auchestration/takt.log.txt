# 調査計画: 非同期人間レビューを組み込んだ AI エージェントワークフロー基盤のローカル検証

## 1. 依頼の分解

### What（何を知りたいか）

1. 仮説検証: Strands 単体では非同期人間確認（ワークフロー中断 → 人間の OK/NG を非同期受領 → OK なら続行、NG なら適切な範囲から再実行）は実現できないのではないか
2. 上記を実現するための技術要素の組み合わせ（AgentCore / Step Functions / 自前の状態永続化 + sqlite3）と、それぞれの良しあし
3. チェックエージェントによる差戻し・再生成ループ（上限付き）の実現方式
4. オーケストレータの実現パターン比較（Step Functions 静的フロー / オーケストレータ AI の動的呼び分け / AgentCore Runtime 寄せ）
5. ローカル実験と本番 AWS の差分

### Why（なぜか・推測）

実組織のロールを AI エージェント化したワークフローアプリを AWS 上に構築する前に、最大の不確実性である「非同期人間レビュ ーの組み込み方」と「オーケストレータの動かし方」を、ローカルで安価に検証して技術選定の根拠を得たい。

### Scope（どこまでか）

- 調査 + 実装実験 + 報告書まで。実験はローカル完結（LLM は port 11434 の OpenAI 互換サーバ）
- AWS 実環境へのデプロイは範囲外。マネージド固有の差分は資料に記載して諦める
- 役割定義・ワークフロー定義は簡易な自作サンプルでよい

### 仮定（明示）

- 仮定1: 「Strands」は AWS の Strands Agents SDK（Python、PyPI: `strands-agents`）を指す
- 仮定2: 「AgentCore」は Amazon Bedrock AgentCore（`bedrock-agentcore` SDK と `agentcore` CLI によるローカル実行を含む）を指す
- 仮定3: 11434 のモデル名（opus 等）は実体不明なため、実験題材は小規模タスク（例: 短文ドキュメント生成 → チェック → 差戻し）とし、モデル性能に依存しない設計にする
- 仮定4: 「非同期」とは、ワークフロー実行プロセスが人間の応答を待ってブロックし続けるのではなく、一旦停止（プロセス終了 可）して、後から届く OK/NG で再開できることを指す

## B. AgentCore のローカル実行
- コンポーネント: Runtime / Harness / Memory / Gateway / Identity / Code Interpreter / Browser / Observability(+ Payments, Evaluations, Optimization, Policy, Registry)。

対象バージョン: strands-agents 1.50.1（PyPI、2026-07-24 リリース）。実コードは github.com/strands-agents/harness-sdk main（旧 sdk-python。リポジトリはモノレポ harness-sdk に改名済み、GitHub API の 301 リダイレクトで確認）。取得日 2026-07-26。

## 主要な発見のサマリー（A の判定）

「プロセスをまたいだ中断・再開が SDK 機能単体で可能か」→ 可（条件付きの注意あり）。

- 現行 SDK には interrupts 機能が正式実装されている（2025-10 の PR #987 以降に段階導入）。tool / hook（BeforeToolCallEvent）から `interrupt()` を発火すると `AgentResult.stop_reason == "interrupt"` で停止し、`{"interruptResponse": {"interruptId": ..., "response": ...}}` を渡して再開する。公式 doc: strandsagents.com/docs/user-guide/concepts/interrupts/
- クロスプロセス再開は SessionManager 併用で公式サポート。実コード裏付け: `strands-py/src/strands/types/session.py` の `SessionAgent.from_agent` が `_internal_state = {"interrupt_state": agent._interrupt_state.to_dict(), ...}` を保存、`interrupt.py` の `_InterruptState.to_dict()` docstring は "Serialize to dict for session management."
- Graph / Swarm も `session_manager` 引数、`serialize_state()/deserialize_state()`、`Status.INTERRUPTED`、`_resume_from_session` を持ち、ノード単位の途中再開（クラッシュ後含む）に対応（`multiagent/graph.py`, `multiagent/swarm.py` で確認）
- 機構別: 単一 Agent=可 / Graph=可 / Swarm=可 / Workflow（tools のツール）=条件付き可（ファイル永続化でタスク単位再開は 可能だが pause/resume アクションは未実装。doc の「Pause and resume workflows」記述は実装より先行）/ Agents as Tools=条件付き可（入れ子 interrupt の rehydration またぎ再開に既知バグ Issue #3076、修正 PR #3008 とも open）/ handoff_to_user=不 可（stdin 同期ブロックか stop_event_loop のみ。interrupt ベース化が Issue #3243 で進行中）

## セッション永続化仕様

FileSessionManager（デフォルト `~/.strands/sessions/`、0o700）と S3SessionManager、カスタム SessionRepository、サードパ ーティの AgentCoreMemorySessionManager。保存対象は messages・agent.state・conversation_manager_state・interrupt_state（_internal_state 経由）。マルチエージェントはオーケストレータ状態を multi_agent.json に保存し「ノード完了ごとに保存、最後 に完了したノードから再開」。制約: スレッド非安全、オーケストレータ内の子 agent に個別 session manager を持たせるのは禁止。

## B. モデルプロバイダ

3 方式とも公式サポート。OpenAIModel は `client_args={"base_url": ..., "api_key": ...}`（公式 doc にカスタムエンドポイン ト例あり）、OllamaModel は `OllamaModel(host="http://localhost:11434", model_id="llama3.1")`、LiteLLMModel は `client_args` に `api_base`（Proxy は `use_litellm_proxy: True`）。インストールは extras（`strands-agents[openai|ollama|litellm]` ）が必要。

## C. Observability

`setup_console_exporter` は実在。`strands-py/src/strands/telemetry/config.py` の `StrandsTelemetry` に `setup_console_exporter(self, **kwargs) -> "StrandsTelemetry"`（kwargs は ConsoleSpanExporter へ）、`setup_otlp_exporter(self, **kwargs)`、`setup_meter(enable_console_exporter=False, enable_otlp_exporter=False)`。メソッドチェーン可。OTLP は標準 otel 環境変 数（OTEL_EXPORTER_OTLP_ENDPOINT 等）で設定。完全カスタムは tracer_provider 注入。

## D. AgentCore

デプロイは `bedrock-agentcore` SDK（`BedrockAgentCoreApp` + `@app.entrypoint` + `app.run()`、port 8080 / ARM64）+ AgentCore CLI（`agentcore create/deploy/invoke`）。非同期は `/ping` の Healthy / HealthyBusy で制御（idle 15 分で終了、`add_async_task`/`complete_async_task`、maxLifetime 例 8 時間）。HITL を直接扱う AgentCore 公式ドキュメントは未発見で、Strands interrupts + セッション永続化 + 同一 runtimeSessionId 再 invoke の組み合わせになるという整理は推論と明記した。

## 注意点・リスク

- ドキュメント URL 体系が `strandsagents.com/docs/...` に移転済み（旧 `latest/documentation/...` は 404）。リポジトリも sdk-python → harness-sdk へ改名。二次記事や古い情報は「中断・再開不可」と記述している可能性が高い（interrupts は 2025-10 以降の機能）
